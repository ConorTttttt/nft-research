# Phase 2 – recovery of exclusive authority

**An incomplete transfer can sometimes be abandoned safely even when some witnesses already signed it.** The decisive evidence is a set of witnesses that permanently close the input and attest which proposal, if any, they reserved. When each possible transfer has enough negative reports, even a hidden certificate is impossible. Every qualifying report set produces the same pre-authorised refund child. The rule deliberately stalls when the evidence is ambiguous. [Derivation](mathematical-theorems.md) · [Executable temporal model](formal-models/temporal.py)

| Research question | Answer |
|---|---|
| A. Arbitrary rollback? | No for freely chosen successors, irreversible offline acceptance and progress after restoration of all enforcing state and signing keys to their pre-transfer images. A buyer can retain a hidden certificate across the restore. [Indistinguishability argument](recovery-impossibility-analysis.md) |
| B. Minimum recovery mechanism? | Finish the exact authorised prior decision or prove all incompatible decisions impossible, including future signatures from unfenced instances. For an unconditional fixed refund in this one-round report model, k reports suffice precisely when k minus the largest prior-digest count exceeds n−q+e. Resolving every contested input requires stronger pre-finality evidence or a different acceptance contract. |
| C. Disjoint witness mobility? | Yes for a child whose *predecessor's final decision* uniquely binds the new policy. Abandoning the existing policy for the same unresolved predecessor can fork with zero malicious operators. [Handoff](witness-handoff-analysis.md) |
| D. More general primitive? | Treat a version as an exclusive right to make an admissible resource rewrite. A partial commutative resource algebra expresses extent, frame and conservation. Classical data remain copyable. Certification enforces one use across machines. [Algebra](exclusive-authority-algebra.md) |
| E. Lower coordination? | Independent enduring rights can advance separately. Conditional programs with a unique result for compatible evidence can be exercised locally after setup. A fresh choice among incompatible successors still requires arbitration. Immediate revocation and unencumbered-title promises introduce shared guards. |
| F. Compact finality? | A root quorum and a Merkle path prove an individual acquisition under honest full-batch validation. The buyer can verify it with the parent proof offline. Auditing siblings, reconstructing a lost certificate and guaranteeing data availability are separate requirements. [Proof semantics](compact-finality-proofs.md) |
| G. Best architecture? | For a bounded-fault federation accepting occasional stalls, choose quorum-certified inputs, deterministic evidence-based refunds and compact receipts. For mandatory contested progress, adopt a reviewed BFT protocol from inception. [Decision gates](architecture-decision.md) |
| H. What costs change? | An extra independent witness and an extra signature at 8/6 buy tolerance for one additional forgetting identity with two silent. Finality depends on a lifetime equivocation bound, trustworthy genesis and retrievable evidence. Permanent fences can sacrifice liveness. [Operational assumptions](rollback-safety.md) |
| I. Strength of evidence? | Impossibility, uniform intersection, the exact report bound and compatible-evidence criterion have explicit derivations. Finite models and real process/Wasmer executions check selected instances. Permissionless admission, universal recovery, a general policy compiler and production safety remain unestablished. [Verification inventory](verification-results.md) |
| J. Improvement over Phase 1? | Reproduced the five-of-seven double certificate using genuine signatures and real process restoration. With six-of-eight the second candidate reached only five. Recovered a real partial split and spent the refund. At 7/5 and width 64 the recipient payload fell from 9,565 to 1,405 JSON bytes. A stock Holochain conductor verified a delayed compact leaf and a reset-to-spend history. [Adversarial tests](adversarial-test-results.md) · [Costs](network-benchmarks.md) |
