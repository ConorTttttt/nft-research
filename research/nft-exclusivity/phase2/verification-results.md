**Transition model.** Authenticated correct owner or Byzantine owner can submit valid proposals; the temporal model maximises the latter's power by enabling both. Honest journals map a version to empty or one prior vote, open or sealed. A vote release makes an unforgeable token available indefinitely. A close emits a signed historical report; restore rewinds local state while old tokens remain in the world. Delays and partitions are arbitrary prefixes and orderings, including permanent withholding. Crashes preserving the journal stutter in the safety model. Key compromise is abstracted as the equivocating identities. The fault placement, number of proposals and restoration depth in the BFS are bounded. The mathematical argument covers arbitrary digests and repeated restoration within the *identity* budget. Reconfiguration is a separate model and induction, rather than an unverified extra action in the fixed-roster checker.

The fallback proof is a monotone predicate over released authenticated evidence; resetting twice creates the same version. We check its possible coexistence with any final transfer. The BFS does not model filesystem or crypto implementation correctness. No fairness assumption is used for safety; there is no unconditional progress proof. See [theorems](mathematical-theorems.md) for conditional liveness and [network tests](adversarial-test-results.md) for authorisation and crash evidence.
