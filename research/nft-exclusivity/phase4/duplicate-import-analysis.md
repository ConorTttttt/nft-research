# Canonical source export and legacy clients

Identify a source by the full typed source DNA hash and mint Create action hash, plus the authenticated current title version. A different clone is a distinct realm unless an explicit migration lineage says otherwise. Do not collapse two real mints by content hash, key core or metadata. Import proof needs a certified source decision binding destination realm, destination committee, resource version, controller and export nonce. Its child ID is deterministic. Replaying the same export on the destination has one effect.

If two destination rosters each accept an owner's signature without intersecting source authority, both can accept the same source asset. Hashing both destination IDs only ensures the duplicate claims have different names. Pinning one canonical destination prevents duplicates among clients that enforce the pin. It does not prevent a source spend. A DHT lookup for previous exports gives no exclusion during a partition.

The model enumerates all orders of two exports and a legacy transition. With independent import gates it recognizes two CEL titles. A common source fence limits it to one; enabling an independent legacy path gives two recognized economic claims again. Source-level migration must prevent future native transfers **and** settle or exclude previously issued hidden transfers from the same parent. An updated client rejecting transfers after a visible export alone is inadequate. Previously forked history cannot be adjudicated by a newer committee absent explicit reconciliation authority.

hNFT's coordinator sorts visible receipts by sequence and refuses a gap or duplicate. Its old clients may still accept a contiguous legacy receipt on their branch. Existing receipts remain historical evidence and continue to have whatever economic meaning those clients assign them. There is no source-level export fence in this experiment. The mint reference used by the sale is fixture provenance supplied out of band. CEL title and legacy title can continue to circulate independently. Require coordinated acceptance cutover or label the new claim as a wrapper with explicitly weaker exclusivity.
