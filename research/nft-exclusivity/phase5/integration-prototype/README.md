# Laboratory proof and native evidence

The P5J1 prototype recognizes exactly one experimental policy profile. Every caller pins the entire policy and the sale terms before verification. A policy admits the test origin version, source and destination realms, epoch, payment capacity/version and denomination, keys and ordered rosters. The amount and beneficiary are checked against this policy. An installation must authenticate those inputs and validate source existence, credit and title ownership before admitting anything. The test provisions them directly. It references real mint and park IDs as provenance labels; creating multiple simulated fixture partitions conveys no claims on that real park.

A proof is ASCII P5J1 followed by canonical JSON under Python's sorted-key, no-whitespace, ASCII encoding. The frozen test schema uses integers, strings, lists and maps only. Verification re-encodes the payload and caps it at 16 KiB. Policy/terms are trusted local configuration. A certificate consists of [body, ownerSignature, indexedVotes]. The body contains the policy digest, typed input version and operation/target. Each fixed domain prefix starts with P5J1/, ends with NUL and is followed by canonical JSON under SHA-256. Five distinct ordered signatures from a pinned seven-member roster and the owner sign the decision digest. Every diary locks a typed input **across targets and operations** before signing. Separate signing keys, in-memory ownership, one local host, one SQLite file per logical witness. SQLite rollback or compromise of three same-roster keys exceeds the model. This experimental encoding has no compatibility claim with the existing CEL wire format.

The source export binds one destination and determines its import ID. Title and payment prepare concurrently on exact immutable terms. FinalPaid requires both preparations plus verified export. FinalVoid proves impossibility of that sale by a valid decline or an irrevocable different choice on the *same* input version. Only an input actually prepared for this sale gets its rollback successor; the foreign resource continues under its own decision. Repeated proof verification is idempotent. With neither positive nor exclusion proof the result is Pending. A known unavailable dependency can be reported as UnavailableEvidence. Invalid is reserved for malformed or mismatched recognized evidence. Native mode abstains on historical evidence and rejects lab certificates. Caller must authenticate any “missing” indication as a retrieval status only. It never affects ownership.

The lab implements onward signatures and tests them for every outcome. Recipient/owner identity derives from the verified outcome. There is no deployed cross-DNA validator or wallet. The source's recognition of export, the payment issuer's exclusive authority, live backing and retention are explicit laboratory premises. Authority migration requires the old epoch to export to the pinned new one. Arbitrarily changing a policy pin is a change of economic contract.

The archived onward fixture is independently checkable after producer exit. This test profile restricts onward signatures to the first five ordered title members. The verifier requires a matching *local title* preparation even on FinalVoid. A foreign payment decision alone can exclude a sale but cannot create an exercisable title. Substituting the onward recipient invalidates the signature.
