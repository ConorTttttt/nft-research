# What a recipient verifies

Every grant uses two independently admitted origins. The experimental policy digest commits to both rosters, origin/parent versions, destination policy, principals, amount and unit. A sale digest additionally binds immutable agreement/version and outcome predicate. This is a deliberately narrow two-domain laboratory profile. The native historical verifier has a different trust root and encoding. A relying party obtains policy and intended grant through an authenticated channel before accepting evidence supplied by a counterparty.

| Evidence | Statement and dependencies | Status of implementation |
|---|---|---|
| Signed payer prefix | Exact signer and native DNA genesis, consecutive hash-linked action sequence, identified funded acceptance preceding named parked action. Requires a pinned tip, payer, acceptance and DNA. | Rust CLI bounds input to 512 KiB and 256 actions, recomputes ActionHash and checks signatures over typed action bytes. Independent five-record verifier checks application entry hashes and financial fields. Historical statement. |
| Source admission | Unique spendable liability or title version with authenticated remaining amount/current controller and exhaustive economic exit coverage. Includes fee/credit and migration policy. | Supplied by laboratory genesis; native admission for irreversible purposes unresolved. |
| Source export → destination import | Five distinct authorized durable source votes and owner consent to one target under a pinned source version. Import child ID follows from source parent and target. Replay has one economic meaning. | Laboratory export certificate; no native legacy cutover. Epoch handoff requires an old-authority export. |
| Bilateral intent | Two immutable resource choices for the same digest. Externally bind the buyer/seller keys to the authentic participants on each native network. | P5J1 documents and signature-domain implementation. Two separate rosters with fixed membership; valid decisions for other policies cannot serve as foreign-choice exclusion evidence in this profile. |
| Conditional title / payment reserve | Signers of each input attest PREPARE(g) or a permanent exclusive alternate decision. Five valid ordered signatures and owner approval bind exact policy and parent. | Lab verifier checks exact parent, source authority and policy. No claim on actual native funds. |
| Execution evidence | Historical template, agreement and RAVE determine allocation. Collection names that RAVE. | Actual signed official-release records; economic verdict Pending. |
| Final effects | Paid requires both matching preparations; Void needs an irrevocable incompatible same-version choice. No discretionary terminal signer. Local return requires evidence that this sale actually prepared the corresponding input. | Implemented for fixed sale and NFT successor. Arbitrary scripts and generic native payment respend outside this implementation. |
| Recovery | Complete proof bytes plus pre-existing trusted roots. Retrieval is retryable; reports of unavailability convey no authority. | Separate process authenticated a surviving lab proof and onward transfer. Phase 4 closure requires permanent authenticated exclusion; no native emergency override is recognized. |

FinalPaid/FinalVoid refer to vested entitlements under that specific policy. An honest reader missing a member of a partially assembled proof normally sees Pending. A failed dependency fetch may be surfaced as UnavailableEvidence. Evidence invalid under the pinned schema or policy is Invalid. Neither status permits an alternative disposition. A validated historical claim can be genuine even when exclusively final settlement remains Pending. Repeated execution must consume deterministic successor versions before spending again. Historical evidence alone does not attest that the buyer still controls the asset after an onward transfer. [Experimental wire contract and decoder](integration-prototype/README.md)
