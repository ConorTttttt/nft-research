# Export and legacy recognition

The tested mint was produced by hNFT's Holochain 0.7.1 compatibility revision 30da888cf5cfdd67561a3dac0d9ff2e32757fc4a. Its Create action identifies the mint in a source DNA. Content and owner key alone identify neither the mint nor the current version. The integrity transfer module loads signed commitments and receipts and checks the correct author, named buyer, previous state, sequence and time window. Duplicate-offer and buyer acceptance checks walk a specified author's ancestry ending at a particular chain top. Receipt and cancellation compare different authored action timestamps to the commitment's deadline. The coordinator derives current_owner by sorting linked receipts and rejecting a noncontiguous visible sequence. A complete visible contiguous lineage is a historical statement conditioned on the view. **Compatibility theorem.** Fix a legacy verifier L and historical input h it accepts. If exporting into a separate realm does not change L's code, trust roots or h, then L(h) has the same result after export. A destination certificate alone cannot force all old readers to reject legacy title. Export exclusivity is a property of precisely named recognizing systems. A new DNA hash authenticates a new rule set; it cannot retroactively change the old one. Existing hidden signed sales must be excluded or explicitly adjudicated before an import promises unencumbered title.

| Mechanism | Required enforcement and outcome |
|---|---|
| Registry or canonical realm only | Prevents duplicate imports among clients pinning it. It leaves old title transferable under legacy recognition. |
| Native fence | Every recognized transfer and export of a version shares a durable decision. A source export consumes the parent and names one destination and initial controller. Prospective issuance under this rule is simpler than retrofitting previously circulating titles. |
| Certified migration | Destination independently verifies source policy, origin/version, exclusive export, destination policy and owner. Import ID is deterministic. Exact replay delivers the same claim. Reject wrong DNA, stale version or epoch and require old export for a disjoint successor committee. |
| Joint migration | Source freezes, destination prepares and both consume a common certificate. Supports extra destination conditions, costs another readiness dependency and may lock on missing evidence. A unilateral timeout is unsafe. |
| Legacy cutover | Publish an agreed final checkpoint and recognition policy that settles prior hidden liabilities; economic participants must actually adopt it. If they continue honoring legacy title, label the result as a wrapper. |

The laboratory signer fenced an export to one realm and refused a second target. It pre-admits the origin and signing policy out of band; the actual hNFT integrity WASM has no such fence. The checked model enumerated two destinations, legacy spends before/after export, replays and a rotated authority over 120 orders per policy. All guarded orders preserved uniqueness. Independent rosters and an independent legacy path each failed in 120 orders; starting the new epoch on the old unresolved version failed in 90. Epoch/clone pinning is necessary: a new DNA is distinct until an authenticated old decision maps it. Source-chain forks are represented as independent accepting histories in the broken model. No release conductor recognized two competing native titles in these experiments. The hNFT certified-ownership research branch differs from main in five model/document files; no production transfer-validator replacement was found in that diff.
